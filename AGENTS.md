# AGENTS.md

## Цель проекта

Джейлбрейк iOS 27 (iPhone 15 Pro Max, A17 Pro, **24A5390f / 27.0b4**) — как конечная цель. Промежуточный путь: получить kernel r/w или код в незасандбоксенном привилегированном процессе. Паника/DoS — не результат сам по себе; эксплуатируемость отслеживается отдельно от надёжности триггера.

Репозиторий — одновременно раннер-фаззер и исследовательский журнал. Аппарат уже подтверждён: подпись отправлена в Apple (case `OE1107312371417`), disclosure-пакет в `disclosure/apple-security-bounty-2026-09/`.

## Правила (самые частые ошибки)

1. **Журнал — источник истины, не README.** `README.md` устарел (v110, текущий v170). Актуальное: `docs/SPTM_research_journal_part19.md` (§107–§170), исторические части 1–18 рядом. Перед новым вектором читать журнал: множество «многообещающих» направлений уже закрыто контролями (reclaim, repoint-write, scaler cross-process, destroy-UAF, sel7-lifetime, HID, JPEG, Mach 0/132). Повторно их не открывать.
2. **Не обновлять устройство с 24A5390f.** В 27.0b5 закрыт bad_query (traversal в `container_query_operation_set_part_domain`) — единственный подтверждённый sandbox escape. Также не переставлять профиль: `ent.plist` несёт 5 app-groups, без них escape мёртв.
3. **Отрицательный результат не считается, пока детектор не показал срабатывание на заведомом входе** (§144 — провал собственного детектора крашей). Пять раз выводы «крашей нет» были ложными. Правила: сначала фаза с гарантированным крашем, потом измерение.
4. **Лог — улика только если он от ЭТОГО прогона.** Молчаливо-устаревший лог уже несколько раз читался как результат. Всегда использовать `relay/runf.sh` (убивает предыдущий процесс, труncates лог, проверяет маркер `[tag]`) — не запускать фазы вручную через devicectl без этой проверки.
5. **Контроль в каждой фазе.** Список owned-id / baseline / контрольное имя обязан присутствовать: без него «0 из N» неотличим от сломанного инструмента. Это повторяющийся класс ошибок проекта (§131, §135, §145, §146, §167–§169).
6. **Читать комментарии-дизеймеры в коде фаз**: многие фазы намеренно паникуют устройство; перед запуском старой фазы сверяться с соответствующей секцией журнала.

## Инструменты и команды

Сборка — прямой clang, Xcode-проекта нет:

```sh
./relay/build.sh                    # -> build/fuzz27.app (+ libiotrace.dylib, подпись)
```

Запуск одной фазы (основной цикл работы):

```sh
./relay/runf.sh <tag> FUZZ_LOGFILE=1 FUZZ_<PHASE>=1 [ENV=VAL ...]
# tag должен совпадать с тегом логов внутри фазы ([bq], [lsvc], ...) —
# иначе runf честно скажет "phase may not have run" (exit 2)

./relay/run_phase.sh results/run-xxx.log <wait_secs> FUZZ_<PHASE>=1 FUZZ_LOGFILE=1
```

- Фазы переключаются env-переключателями `FUZZ_*`; диспетчер — конец `fuzzer/t_iosurface_scaler.m` (цепочка `if (getenv("FUZZ_..."))`, ~line 28117+). Новая фаза добавляется туда же.
- devicectl на этом билде не принимает `--console` + env: конфиг передаётся как `KEY=VAL` в argv, `fuzzer/main.m` парсит их в окружение.
- `FUZZ_LOGFILE=1` обязателен — иначе stderr не пишется в `Documents/fuzz.log` и лог не вытащить.
- `FUZZ_MODE=vcpdrm|scaler|mig|xpleak|all` (default `all`) — воркеры в `fuzzer/main.m`.
- После серии крашей канал впадает в crash-loop throttle (~10 мин пауза, ребут не нужен); после ребута — `relay/resume.sh`.
- `python3 relay/relay.py <минуты>` — цикл pull→build→install→launch→collect→**commit+push results/**. Stateful: не указывать на ветку, где это неожиданно.
- Кекстры/статика: `relay/get_kc27.py` (достаёт kernelcache из IPSW), карв-скрипты и `kext_strings.py`, `bound_audit.py`, `xref_maestro.py` в `results/securerom/` и `results/kc-extract/`. Карв-бинари (`results/kc27/*.macho`) в git не коммитить (см. `.gitignore`), их можно открыть в IDA через доступный MCP.
- Коды возврата путают: `0x2e2` = NotPermitted, `0x2c1` = NotPrivileged (это исправление §143, не путать). `0x2c2` = BadArgument — почти всегда «формат/гейт», не баг.

## Карта поверхности (не тратить время повторно)

Измерено: IOKit 5/460 открыто и все закрыты (§142–145); Mach 0/132, lookup перехвачен (§146); из 265 кекстов программно-достижимых входов нет (§169). Живые направления на v171:

- **bad_query** (`fuzzer/bad_query.c`, фазы `p_bq`/`p_bq2`/`p_bq3`/`p_bq4`) — **читающий и пишущий примитив во все системные контейнеры** (§172/§175/§176): W-open 22/22, create 63/63 без отказов, write-back `write(2)` на 4 файлах с побайтовой сверкой; изменение plist `lsd` (добавление ключа) сделано и побайтово откатено по шаблону «контроль→бэкап→изменение→детект→откат»; release ревокает (фазы изолированы); part 2 открывает другое дерево, чем part 3; self-minting токенов закрыт EPERM; канал наблюдения за реакцией демона из песочницы закрыт (LSCopy*-символов нет, LSApplicationWorkspace фильтрует ответ);
- **внешний тест** (`p_bq5`/`p_bq6`, §177/§178, **ПРОЙДЕН ПОЛОЖИТЕЛЬНО**) — цель выбирается измерением активности (`p_bq6`: stat-снапшот+diff, только stat, безопасно), не наугад: `DefaultAppQueryState` — H0 даже после reboot (мёртвый файл), а `findmydeviced.accessories.plist` демон перечитывает каждые минуты — CHECK дал `REWRITTEN-BY-DAEMON`; канал «пиши → демон читает» подтверждён; для живого файла критерий чистоты — отсутствие нашего ключа, не байтовая идентичность (гонка с демоном); **подмена содержимого (§180, v176c) закрыта как негатив**: plist — NSKeyedArchiver, патч name-слота (`objects[14]`) дал DAEMON-REPAIRED — файл есть OUTPUT демона (витрина), не вход; влиять через него правками нельзя; живые кандидаты-«файлы-входы» из bq6: активная SQLite `8EB68272/db`, кэш `functions.{data,list}`;
- **сеть** — логи v163–165 сохранены (`results/v171-{net,lsvc,ipopt}.log`, §171/§173): raw EPERM, открыт только TCP 1080, **IP_OPTIONS принимает легальные опции включая LSRR** (§165 ошибался на формате 13 байт) — парсер опций IP достижим и остаётся живым вектором; SCTP/UDPLITE/MPTCP в ядре нет (EPROTONOSUPPORT), sysctl/ioctl-записи закрыты EPERM;
- **привилегированные демоны через loopback** — mDNSResponder не отвечает ни в одном из 7 форматов/адресов с валидным детектором (§174, остался внешний тест `dns-sd` с Mac), TCP 1080 принимает и закрывает без протокола; через публичные фреймворки — не пробовались;
- **static-лид** §169: AppleMSG (11 upper / 0 lower) — ручной разбор арифметики, автоматизация исчерпана.
